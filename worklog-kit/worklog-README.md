# 업무일지 (worklog)

이 폴더에는 이 프로젝트에서 Claude Code 로 한 일이 날짜별 파일(`YYYY-MM-DD.md`)로 쌓입니다.
기록은 Claude 가 씁니다. 내가 따로 적거나 프롬프트로 부탁하지 않아도 됩니다.

## 어떻게 쌓이나

| 시점 | 무엇이 일어나나 |
|---|---|
| 세션 시작 | Claude 에게 이번 세션 헤더 틀(세션 번호·이름)을 보여줍니다 |
| 첫 파일 수정 직전 | 이번 세션 헤더(왜·무엇을)가 없으면 수정을 막고, Claude 가 헤더부터 씁니다 |
| 파일을 고칠 때마다 | `- 21:35 [Edit] 고친파일 (session:번호)` 한 줄이 자동으로 붙습니다 |
| 스크립트 실행·커밋·발송 | `- 21:40 [Bash] \`git push\` (session:번호)` 처럼 자동으로 붙습니다 |
| 답변을 마칠 때 | 고친 게 있는데 결과 줄이 없으면 한 번 막고, Claude 가 결과를 씁니다 |

물어보기만 하고 아무것도 바꾸지 않은 대화는 기록하지 않습니다.
명령 원문은 남기지 않습니다. 프로그램 이름과 옵션 이름만 남겨서 비밀번호·토큰이 기록에 섞이지 않게 합니다.

## 한 세션의 모양

```
## session:1a2b3c4d — 내 이름
- 목적/왜: ...
- 무엇을: ...
- 21:35 [Edit] notes/plan.md  (session:1a2b3c4d)      ← 자동
- 결과(1a2b3c4d): ...
```

결과 줄은 `- 결과(번호):`, 아직 진행 중이면 `- 중간(번호):` 로 써야 자동 점검이 알아봅니다.

## 작성 기준 (Claude 가 이 수준으로 씁니다)

| 항목 | 반드시 들어갈 것 |
|---|---|
| **목적/왜** | 계기(무슨 일이 있었나, 누가 부탁했나) + 왜 지금 하는지 |
| **무엇을** | 고칠 범위 + **손대지 않는 것** |
| **결과** | ① 실제로 바뀐 것과 그걸 찾아갈 단서(파일 경로·커밋·링크·문서의 행) |
| | ② **어떻게 확인했나**(다시 열어봄·실행해봄·미리보기). 확인 못 했으면 '미확인'이라고 |
| | ③ **못 한 것·남은 일**. 숫자는 출처와 대조한 것만 |

좋은 예:

```
## session:1a2b3c4d — 슬기
- 목적/왜: 주간 회의록이 폴더 세 곳에 흩어져 있어 지난 결정을 찾는 데 매번 10분씩 걸린다
- 무엇을: meetings/ 아래 2026-09 회의록 12개를 날짜순 한 파일로 합치기. 원본 파일은 지우지 않음
- 21:35 [Write] meetings/2026-09-합본.md  (session:1a2b3c4d)
- 결과(1a2b3c4d): meetings/2026-09-합본.md 생성(회의록 12개, 날짜순). 원본 12개와 제목·날짜를 한 줄씩
  대조해 빠진 것 없음 확인. 9/17 회의록은 결정 사항 칸이 비어 있어 그대로 둠(직접 채워야 함)
```

나쁜 예: `- 결과: 회의록 정리 완료` (무엇이 바뀌었는지, 확인했는지, 남은 게 있는지 알 수 없음)

## 설정

- **이름:** 기본은 git 이름, 없으면 맥 사용자 이름입니다. 바꾸려면 `~/.claude/settings.json` 에
  `"env": { "WORKLOG_AUTHOR": "내 이름" }` 을 넣습니다
- **끄기:** 이 프로젝트의 `.claude/settings.json` 에서 `.claude/hooks/worklog/` 가 들어간 줄을 지웁니다
- **업데이트:** 설치할 때 쓴 한 줄 명령을 다시 실행하면 됩니다(기존 기록은 그대로)
