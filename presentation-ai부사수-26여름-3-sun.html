Q. 엔비디아 모델도 클로드 코드로 설치·사용 가능한가요?
A. 네. 클로드 코드에게 '엔비디아에서 무료 키 받아서 이 모델 불러줘'라고 부탁하면, 연결 코드를 대신 써주고 설치부터 호출까지 옆에서 도와줍니다. 엔비디아 방식이 표준(오픈AI 호환)이라 주소·키만 바꾸면 되기 때문입니다.

클로드 코드는 클로드 위에서 돕는 부사수, 엔비디아 모델은 그 부사수가 연결해주는 도구입니다. 코딩을 몰라도 오늘 T로 도전해볼 만합니다.

이번 2주, 무료로 바로 써볼 것

비개발자도 오늘 그대로 따라할 수 있는 것만 골랐습니다. 셋 다 무료로 시작합니다.

① 스킬 = 남이 만든 걸 그대로 설치

디자인 스킬 수십 개(60~90개대)가 무료로 열렸습니다. 화면 녹화 영상을 주면 레이아웃·색·모션까지 프롬프트로 바꿔줍니다. 글쓰기 스킬 5종도 있습니다: 쉬운 말로 다시 쓰기 / 계속 읽히는 이야기 구조 / 첫 문장(훅) 고치기 / AI 티 걷어내기 / 내 글 20개 배워 내 말투로.

체감: 매번 프롬프트를 짜는 대신, 잘 만든 스킬 하나를 받아 씁니다.

② 요청하는 법이 달라졌다

앤트로픽 개발자(Thariq)가 공유한 요청법이 X에서 크게 화제가 됐습니다. 시작 전에 "내가 놓친 것부터 알려줘"라고 먼저 묻고, 완성본 1개 대신 시안 4개를 먼저 받고, "AI가 나를 인터뷰하게" 만드는 방식입니다.

체감: 오늘 워크숍 순서(맥락 → 작은 목표 → 반복)가 그대로 이 방식입니다.

③ 가장 센 모델, 쓰는 법이 다르다

Fable 5는 "며칠짜리 일을 통째로" 맡기는 모델입니다. 쉬운 일만 시키면 저평가하게 됩니다. 구 모델에서 쓰던 프롬프트 습관은 오히려 방해가 되니, 지시를 줄이고 "목표와 이유"를 줍니다. 가장 어렵고 불확실한 일에만 여기에, 나머지는 싼 모델로 나눠 씁니다.

체감: 다음 회차 T 워크숍에서 "큰 일 하나"를 통째로 맡겨봅니다.

내가 클로드 코드를 어떻게 쓰는지 리포트로 받아본다

채팅창에 /insights 한 줄이면, 최근 30일 동안 내가 클로드 코드를 어떻게 써왔는지 정리한 리포트(HTML)를 만들어줍니다.

무엇을 보여주나

  • 주로 어떤 일에 많이 썼는지 (작업 종류 분포)
  • 세션이 얼마나 효율적이었는지, 토큰은 얼마나 썼는지
  • 자주 막히거나 되돌린 지점 (마찰 포인트)

/usage와 뭐가 다른가

/usage는 지금 이 순간의 비용·사용량을 즉시 보여주고, /insights는 한 달치 패턴을 분석해 리포트로 묶어줍니다.

왜 좋은가
"내가 클로드를 어디에 쓰고, 어디서 자꾸 막히는지"를 눈으로 보면 다음에 뭘 스킬로 만들지가 보입니다.

S in Detail

S = Start — 미뤄왔던 일을 시작하는 칸

"매일 하면 좋은데 자꾸 미루는 것들" — AI에게 그 일을 매일 옆에서 도와달라고 부탁하는 영역.

S 영역의 특징

  • 실패해도 부담이 적음 — 어차피 안 하던 일이니까
  • 성과보다 빈도가 중요 — 매일 짧게 하는 게 성공
  • 결과물보다 트리거가 먼저 — "AI가 먼저 말 걸어주는 구조"가 절반
  • 나를 위한 일 — 회사 KPI가 아니라 내 삶의 작은 루틴

슬기의 S 영역 4개 (실제 운영 중)

  • /hello-world — 아침에 캘린더·미리알림·어제 잔여 작업을 한 화면에 띄워주는 브리핑
  • /run-daily-note — 하루 끝에 그날 작업을 자동으로 일지로 정리
  • /cleanup-home — 흩어진 다운로드 파일을 자동 분류
  • /backup-notes — 노트를 주기적으로 백업

공통점: 전부 "매일 해야 하는 줄 아는데 자꾸 까먹는 것"이었음.

S in Detail

S 영역 스킬은 어떻게 작동하는가

예시 1 — /hello-world

아침에 명령 한 줄 입력하면:

  1. 인증 파일이 제대로 있는지 확인
  2. 오늘의 캘린더 일정 가져옴
  3. 미리알림 앱에서 오늘/늦은 항목 가져옴
  4. 어제 작업 일지에서 미완료 항목 확인
  5. 한 화면에 정리해서 보여줌

예시 2 — /cleanup-home

홈/다운로드 폴더를 훑고, 파일 종류·날짜로 자동 분류 폴더에 이동. "이거 어디에 둘까"를 매번 고민하지 않아도 됨.

공통 구조

  1. 트리거 — 언제 시작할지 (아침에, 하루 끝에, 매주 일요일에)
  2. 데이터 소스 — 어디서 정보를 가져올지 (캘린더, 폴더, 슬랙)
  3. 처리 — 어떻게 정리할지 (분류, 요약, 정렬)
  4. 결과 형식 — 어디로 보여줄지 (화면, 파일, DM)

기억할 것
좋은 S 스킬은 "내가 명령하지 않아도 알아서 말 걸어주는 구조"까지 만드는 것. 일단 오늘은 그 직전 단계인 "명령 한 줄로 시작되는 단계"까지 가봅니다.

Workshop · Step 1

STEP 1 — 미뤄둔 일 떠올리기 (5분)

"미뤄둔 일"의 정의

  • "매일 하면 좋은데 안 하고 있는 것"
  • "한 번 시작하면 좋은데 시작이 안 되는 것"
  • "머릿속엔 있는데 손이 안 가는 것"

업무도 좋고, 개인 영역(독서·운동·가계부)도 좋음.

예시 (참고용)

  • 매일 아침 어제 한 일 한 줄로 정리하기
  • 주말마다 다운로드 폴더 정리
  • 읽고 싶은 기사 모아두고 매일 한 개씩 요약
  • 매주 월요일 한 주 캘린더 미리 보기
  • 가계부에 어제 결제 내역 기록
  • 슬랙 중요 메시지 모아두기

활동 — 노트를 펴고 3개를 적어보세요. 잘 안 떠오르면 위 예시에서 가장 비슷한 것을 골라도 됩니다.

Workshop · Step 2

STEP 2 — 가장 가벼운 1개 고르기 (5분)

고르는 기준 3가지

  1. 5분 안에 끝나는 것 — 거창한 건 금지
  2. 결과를 누가 검사 안 하는 것 — 회사 KPI 말고 내 삶의 일
  3. 매일 또는 매주 반복되는 것 — 일회성 작업은 R 영역으로

하지 말 것

  • "내 인생을 바꿀 거대한 습관" 같은 거 고르지 마세요
  • "AI가 알아서 다 해주는" 같은 막연한 기대 금지
  • 다른 사람과 협업이 필요한 것은 보류

활동 — 3개 중 가장 작고 가벼운 것에 동그라미 하나. 그것이 오늘 우리가 만들 S 스킬의 주제입니다.

Workshop · Step 3

STEP 3 — 4칸으로 명령 만들기 (10분)

4칸 양식

  1. 트리거 — "언제 이 일을 할 것인가?"
  2. 소스 — "어디서 정보를 가져올 것인가?"
  3. 처리 — "어떻게 가공할 것인가?"
  4. 결과 — "결과를 어디로 보내줄 것인가?"

한 칸당 한 줄이면 충분합니다. 완벽할 필요 없음.

완성 예시 — "매일 캘린더 정리"

# 트리거
매일 아침 9시
# 소스
구글 캘린더 오늘 일정
# 처리
시간순 정렬, 회의 / 개인일 분류
# 결과
~/오늘일정.md 파일로 정리

활동 — 노트 한 장에 4칸을 그리고 각각 한 줄씩 채워보세요. 옆사람과 비교해도 좋습니다.

Workshop · Step 4

STEP 4 — 실제로 실행해보기 (15분)

실행 방법

  1. VS Code에서 클로드 코드 채팅창 열기
  2. 4칸 내용을 그대로 한국어 문장으로 풀어 입력
  3. 클로드가 묻는 질문에 한 줄씩 대답
  4. 결과 확인 — 잘 되면 다음 칸 추가, 안 되면 막힌 부분 같이 풀기

자주 막히는 곳

  • "권한이 없다"는 메시지 → 캘린더/슬랙 등 인증 필요
  • "파일을 찾을 수 없다" → 정확한 폴더 경로 알려주기
  • 너무 많은 걸 한 번에 시키기 → 한 단계씩 나누기

팁: 첫 스킬은 캘린더·슬랙처럼 로그인이 필요한 것보다 내 컴퓨터 파일 정리처럼 바로 되는 일로 시작하면 막힘이 적습니다.

입력 예시 (그대로 써도 됨)

> 매일 아침 9시에
  구글 캘린더 오늘 일정을
  시간순으로 정리하고
  회의/개인일정으로 분류해서
  ~/오늘일정.md 파일로 저장하는
  스킬을 만들어줘.

> 먼저 한 번만 실행해서
  결과를 보여줘.

결과가 마음에 들면 저장해두기. 매일 자동으로 실행하는 건 다음 시간에 다룹니다.

Q. 메일 계정을 여러 개 동시에 관리할 수 있나요?

커넥터는 서비스당 계정 1개만 연결됩니다(두 번째 Gmail을 연결하면 첫 번째를 덮어씀). 대신 MCP 서버를 계정별로 하나씩 따로 붙이면 됩니다.

어떻게 동작하나

Claude Code(터미널·데스크탑·VS Code 아무거나)에서 gmail-개인, gmail-회사 이렇게 각각 다른 이름(alias)으로 등록하면, 한 세션 안에서 두세 개 받은편지함을 같이 읽고·검색하고·보낼 수 있습니다.

# 계정별로 하나씩 등록
claude mcp add gmail-개인 --
  npx -y @shinzolabs/gmail-mcp@latest
claude mcp add gmail-회사 --
  npx -y @shinzolabs/gmail-mcp@latest

각각 등록할 때 해당 계정으로 인증만 하면 되고, /mcp로 둘 다 ✓ Connected 뜨는지 확인하면 끝. (정식 지원은 아님)

From Members · Q&A

Q. VS Code에 Claude vs 데스크탑 Claude Code, 뭐가 다른가요?

디바이스 연동

VS Code·CLI의 로컬 세션도 Remote Control로 모바일·브라우저에서 원격 제어됩니다. Cowork(클라우드 세션)는 데스크탑·웹·모바일(베타)에서 같은 작업을 이어갈 수 있습니다.

→ "VS Code는 모바일과 연동 안 됨"은 정확하지 않습니다.

각자의 강점 (우열 아님)

  • VS Code: 편집기 통합, 인라인 diff, 자동 에러 읽기
  • 데스크탑: 시각적 diff 뷰어, 병렬 세션 관리
  • MCP 연결·자동화(hooks)는 둘 다 동일

선호하는 워크플로우에 따라 고르면 됩니다.
